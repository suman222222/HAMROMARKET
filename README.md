## 📌 Project Overview

HamroMarket is a responsive web application developed by a team of four students as part of the **VCS Summer Class**.

Although the project takes an e-commerce website as a reference, the main objective is to demonstrate a complete collaborative software development workflow using **Git and GitHub**.

The project focuses on:

- Collaborative development
- Version control
- Feature branching
- Pull Requests
- Code review
- Continuous Integration (CI)
- Issue tracking
- Project-board management
- Responsive web design
- Accessibility
- Performance optimization
- SEO
- Final software release

---

## 🎯 Project Objectives

The main objectives of this project are to:

1. Build a functional and responsive web application.
2. Apply Git-based version control.
3. Collaborate effectively using GitHub.
4. Use feature branches instead of working directly on `main`.
5. Track development using GitHub Issues and Projects.
6. Review code through Pull Requests.
7. Use CI to automate quality checks.
8. Test the application across different devices and browsers.
9. Apply accessibility, SEO, and performance best practices.
10. Release the completed project as **v1.0.0**.

## 🔀 Git Workflow

The team follows a branch-based development workflow.

```text
main
 ↓
Create feature/fix branch
 ↓
Develop
 ↓
Commit
 ↓
Push branch
 ↓
Pull Request
 ↓
Code Review
 ↓
CI Checks
 ↓
Merge
 ↓
Delete Branch
````

### Branch Naming

Examples:

feature/homepage
feature/products
feature/cart
feature/checkout
feature/responsive
fix/navbar
fix/mobile-layout
docs/readme
```

### Commit Convention

Examples:


feat: add product listing
fix: resolve mobile navbar issue
style: improve checkout layout
docs: update README
test: add HTML validation

Developers should avoid committing directly to `main`.

## 📋 Project Management

Development tasks are tracked using **GitHub Issues** and **GitHub Projects**.

### MoSCoW Prioritization

#### Must

Features required for the initial release.

#### Should

Important features that improve the application but do not block release.

#### Could

Additional improvements that can be implemented if time allows.

#### Won't

Features intentionally postponed beyond the `v1.0.0` release.

## 🔍 Quality Assurance

Before a feature is merged, the team checks:

* Valid HTML
* Clean CSS
* No unnecessary commented-out code
* No `console.log()`
* No placeholder content
* No broken links
* No broken images
* Images contain appropriate `alt` text
* Forms have labels
* No unrelated changes
* Responsive behavior works correctly

### Browser Testing

The application is tested using:

* Chrome
* Edge

## ♿ Accessibility

The project follows basic web accessibility practices, including:

* Descriptive image `alt` text
* Proper form labels
* Keyboard navigation
* Visible focus indicators
* Logical heading hierarchy
* Sufficient color contrast
* Semantic HTML
* `lang="en"` on the HTML document

Accessibility testing will be performed using **WAVE** and **Lighthouse**.

Performance optimization includes:

## 🔎 SEO

Each important page should include:

* Unique page title
* Meta description
* One primary `<h1>`
* Descriptive URLs
* Meaningful internal links
* Descriptive image `alt` text
* Fast loading performance
* Appropriate semantic HTML

### Example

```html
<title>HamroMarket | Products</title>

<meta
    name="description"
    content="Explore our products and services."
>

<meta
    name="viewport"
    content="width=device-width, initial-scale=1.0"
>
```
